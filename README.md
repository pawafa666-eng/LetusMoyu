两名博士生的异步科研园区。每次花 30 秒到 3 分钟，接课题、攒论文、给搭子留点节目，再一起把实验室建起来。

游戏入口：https://letus-moyu-yiyi-and-fafa-d6gr7w5e62c4e8565.webapps.tcloudbase.com

独立 NPC 信务室：https://yiyi-and-fafa-d6gr7w5e62c4e8565-1330587953.tcloudbaseapp.com/mailroom/

信务室使用 fafa 的游戏账号登录，由服务端 UID 核验管理员权限；不在游戏内放置入口。低空玩家显示名是 Yizi，登录用户名仍为 yiyi。两站使用同一个后端，允许每个账号最多三个原生会话。

1. 用各自的游戏账号登录。账号由园区管理员邀请开通，不开放公共注册。
2. 第一位博士创建园区，设置昵称和研究方向，复制十位邀请码。

## 存档如何工作

**GitHub 保存代码，腾讯云开发文档数据库保存玩家进度。**

- 每次有效操作在服务器事务中完成：校验账号 → 结算时间 → 处理操作 → 写入状态、请求凭据与快照。
- 一次请求使用唯一 UUID。网络中断后重试原请求，服务器识别为同一次操作，不重复扣钱或扣行动力。
- 骰子与待选择事件先保存，再把结果交给浏览器。刷新和换设备不会重摇骰子。
- 行动力按服务器时间每 30 分钟恢复一点，最多 5 点；经营设施每 2 小时产出一份，最多存 6 份；横向任务按实际工期完成，需手动验收拨款。
- 浏览器的 localStorage 只保存登录 SDK 所需会话和待重试请求，不决定经费、项目、骰子或审稿结果。
- 每个园区最多保留最近 12 次写操作的服务端滚动快照。它用于管理员排查和恢复；与当前状态共用环境，不能替代异地灾备。
- “下载一份存档副本”导出可读 JSON。对方手牌、隐藏审稿结果不在副本中；不提供上传 JSON 改余额的入口。
- 服务端快照恢复由管理员核对园区、时间和版本后处理，不自动覆盖两个人的新进度。

清理浏览器缓存只会退出登录，不会删除云端游戏进度。代码更新也不应清空数据库；后续数据格式升级需提供迁移和备份。

## 技术结构

- 前端：Vue 3、TypeScript、Vite、Lucide SVG 图标、Three.js 程序生成的低多边形校园。WebGL 不可用时自动使用 SVG / 2D 轻量地图。
- 认证：CloudBase Web SDK、getSession 会话校验。游戏四位码经每账号独立随机盐和 PBKDF2-SHA256（210000 次）转换成 24 字符的原生登录凭证；原生认证身份与白名单继续生效，不需要密码中转服务。
- 权威规则：Node.js 20 事件云函数 letusMoyu。只允许管理员预置的两个 UID。
- 存储：五个业务文档数据库集合，浏览器直接访问全部关闭，写操作经云函数事务完成。新增 letus_moyu_correspondence 保存会话全文，按 roomId、scopeCivil / scopeAir 与 kind 建复合索引；资料、成果和学生任务保存在园区状态。房间滚动快照与“存档副本”不包含会话全文，完整备份需同时备份邮件集合。

| 集合 | 数据 |
|---|---|
| letus_moyu_rooms | 完整园区快照：玩家、项目、论文、专利、收件箱、招生册、学生、实验室、效果、最近动态 |
| letus_moyu_members | 认证 UID 与园区关联；一个账号仅属于一个园区 |
| letus_moyu_receipts | 请求 UUID 的哈希、操作者、动作和提交时间，防止重复执行 |
| letus_moyu_snapshots | 最近写操作的轮转恢复快照 |
| letus_moyu_correspondence | 玩家和 NPC 往来会话、未读标记、学生附件与邀请结算 |

字段与索引见 [DATABASE.md](DATABASE.md)。
源码只保存每账号公开盐与迭代次数，不保存四位码或原生派生凭证。更改四位码时，需要同步更新该 UID 的原生凭证；不能只改前端校验。新增登录函数的原方案因工具拒绝创建而弃用，未部署该函数；此前建立的空限流集合不参与现有认证。登录仍直接交给原生认证服务处理，会话由官方 SDK 管理。

## 本地开发

需要 Node.js 22.12+，建议 Node.js 24。

~~~sh
npm ci
npm run dev
npm run build
npm run dev:mailroom
npm run build:mailroom
npm test
npm run check:server
~~~

游戏产物在 dist/，独立信务室产物在 dist-mailroom/；后者会将 office.html 入口整理为根目录 index.html。游戏服务 letus-moyu 的 appPath 为 /，信务室服务 letus-moyu-mailroom 的 appPath 必须为 /mailroom/。两服务复用环境静态桶，不能都部署到根目录；独立 CloudApp 子域名不能证明文件隔离。信务室使用上方已实际校验的标准静态托管地址。没有新增服务器或付费定时任务。

本地同时启动两个 Vite 服务时使用不同缓存目录 .vite-game 和 .vite-mailroom，避免信务室的依赖预构建覆盖游戏的 Three.js 缓存。

前端默认使用 src/cloudbase.config.json 中的环境与 **公开 Publishable Key**；该 Key 不是管理密钥，不能直接读写游戏集合。需要切换环境时，用 .env.local 覆盖 .env.example 中的变量，并对应修改云函数环境变量。

正式账号密码、服务端 API Key、腾讯云 SecretKey 都不能提交 GitHub。两个初始游戏账号的密码单独交付给园区主人，不在本仓库中。

本次已从本地前端通过官方 SDK 实际连接云端，完成两个新账号的登录和读取。OAuth 跳转等登录方式仍须按平台要求配置安全域名；不要为联调关闭身份验证或把正式余额改到本地。开发时可打开 /?preview=1 使用独立演示园区，生产构建不提供该演示 API。

后端依赖：

~~~sh
npm ci --prefix cloudfunctions/letusMoyu
~~~

同步配置后构建：

~~~sh
node scripts/sync-content.mjs
npm run build
~~~

真实接口联调需要本机私有账号 JSON（仅含 username、password），不要放在仓库里。当前四位游戏码使用：

~~~sh
node scripts/verify-upgrade.mjs /absolute/path/to/private-game-codes.json --pin
~~~

这条命令先派生原生凭证，再登录、读取和校验原双人园区，不移动或消费。下面的旧脚本用于直接提供原生凭证的低层联调：

~~~sh
node scripts/smoke-cloud.mjs /absolute/path/to/private-accounts.json
node scripts/smoke-cloud.mjs /absolute/path/to/private-accounts.json --exercise
~~~

第一条只登录和读取；--exercise 会创建或加入真实园区、执行一次移动并使用合作牌，验证重复请求与共享动态。会消耗实际游戏行动力，不应在已有游玩进度上反复运行。

## 部署与权限

当前环境位于上海。云函数环境变量：

- CLOUDBASE_ENV_ID：实际完整环境 ID
- ALLOWED_UIDS：两个允许访问的认证 UID，以逗号分隔；不填时拒绝全部玩家
- MAIL_ADMIN_UIDS：可处理 NPC 邮件的认证 UID，以逗号分隔；默认仅 fafa 的既有 UID

五个游戏集合为 ADMINONLY。云函数规则要求已登录，函数内部继续校验双人白名单与园区成员身份。匿名访问、其他环境账号、客户端自报 UID 均不能修改存档。
